Failures generated by Sekisho return `application/problem+json` with a stable `code`, the HTTP `status`, and — when an instrumented build records a request span — a `trace_id`:

```json
{
  "type": "about:blank",
  "title": "Forbidden",
  "status": 403,
  "code": "policy_denied",
  "trace_id": "0123456789abcdef0123456789abcdef"
}
```

## Response headers

`X-Proxy-Outcome` is set on **every** response:

- `forwarded` — the upstream handled the request successfully;
- `upstream_rejected` / `upstream_failure` — the upstream returned a 4xx / 5xx, whose original status and body are kept;
- otherwise, the Sekisho outcome code.

`X-Proxy-Trace-ID` correlates the response with traces and [audit records](/docs/audit) when the request has an OpenTelemetry span. Neither header is trusted from clients or upstreams.

## Codes by phase

| Phase | Codes |
| --- | --- |
| Admission & routing | `rate_limited` (429), `body_too_large` (413), `ambiguous_path` (400), `route_not_found` (404), `method_not_allowed` (405), `routing_error` (500) |
| Authentication | `auth_missing` (401), `auth_malformed` (401), `auth_expired` (401), `auth_invalid` (401), `claims_invalid` (401), `insufficient_scope` (403) |
| Policy | `policy_denied` (403), `policy_error` (403), `claims_invalid` (401), `invalid_query` (400), `invalid_json` (400), `invalid_body_text` (400), `body_read_error` (400), `unsupported_media_type` (415) |
| Identity data | `userinfo_unavailable` / `userinfo_invalid` (502), `userinfo_subject_mismatch` (401), `introspection_unavailable` / `introspection_invalid` (502), `introspection_subject_mismatch` / `token_inactive` (401) |
| Backend credential | `backend_token_unavailable` (502), `backend_token_rejected` (502), `backend_token_invalid` (502), `backend_assertion_failed` (502) |
| Forwarding | `upstream_unavailable` (502), `upstream_timeout` (504), `upstream_stream_aborted` (a stream that failed after headers were sent), `upstream_rejected`, `upstream_failure` |

`auth_invalid` deliberately groups signature, issuer, audience and other verification failures. A route's [`on_deny`](/docs/policies#on_deny) can replace `policy_denied` with its own status and code.
