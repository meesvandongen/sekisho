<Steps>
<Step>

### Install

Download a [release binary](/installation#release-binaries) or pull the [container image](/installation#container-image). No Go toolchain is needed.

```sh
docker pull ghcr.io/meesvandongen/sekisho
```

</Step>
<Step>

### Copy the examples

Every release archive ships the example configuration in its `examples/` directory; the container image has it at `/etc/sekisho`. You can also copy [`config.json`](https://github.com/meesvandongen/sekisho/blob/main/gateway/examples/config.json) and [`api.yaml`](https://github.com/meesvandongen/sekisho/blob/main/gateway/examples/api.yaml) from the repository. Point them at your issuer and API.

<Files>
  <Folder name="examples" defaultOpen>
    <File name="config.json" />
    <File name="api.yaml" />
    <File name="policy-tests.json" />
    <Folder name="policies" defaultOpen>
      <File name="amount.cel" />
    </Folder>
  </Folder>
</Files>

Paths inside the JSON config — the OpenAPI file, CEL files and private key files — are resolved **relative to the config file**.

</Step>
<Step>

### Check it offline

Before contacting an issuer, print the [effective policy](/policies#explaining-the-effective-policy) of every operation and run the [policy fixtures](/testing-policies):

<Tabs items={['Binary', 'Docker']}>
<Tab value="Binary">

```sh
sekisho -config examples/config.json -explain
sekisho -config examples/config.json -test-policies policy-tests.json
```

</Tab>
<Tab value="Docker">

```sh
docker run --rm -v "$PWD/examples:/etc/sekisho:ro" ghcr.io/meesvandongen/sekisho \
  -config /etc/sekisho/config.json -test-policies policy-tests.json
```

</Tab>
</Tabs>

</Step>
<Step>

### Provide secrets

Secrets are never read from the JSON file. Supply them through the environment variables the config names, for example from your secret manager:

```sh
export BACKEND_CLIENT_SECRET="…"
```

</Step>
<Step>

### Run

[OpenTelemetry](/opentelemetry) is configured with standard environment variables:

<Tabs items={['Binary', 'Docker']}>
<Tab value="Binary">

```sh
OTEL_SERVICE_NAME=sekisho \
OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318 \
OTEL_LOGS_EXPORTER=none \
sekisho -config examples/config.json
```

</Tab>
<Tab value="Docker">

```sh
docker run --rm -p 8080:8080 \
  -v "$PWD/examples:/etc/sekisho:ro" \
  -e BACKEND_CLIENT_SECRET \
  -e OTEL_SERVICE_NAME=sekisho \
  -e OTEL_EXPORTER_OTLP_ENDPOINT=http://collector:4318 \
  -e OTEL_LOGS_EXPORTER=none \
  ghcr.io/meesvandongen/sekisho
```

</Tab>
</Tabs>

</Step>
</Steps>

## Startup is strict

Configuration is validated once, at startup, and changes require a restart. Sekisho refuses to start on any of:

- unknown or duplicate fields in the JSON config;
- invalid OpenAPI documents, operations not covered by a policy check, or operations without a single resolvable backend;
- policies that fail to compile or type-check;
- missing credentials for a backend profile that a route selects.

## Command-line flags

| Flag | Description |
| --- | --- |
| `-config <file>` | Path to the JSON configuration file. Required. |
| `-test-policies <file>` | Run [offline policy fixtures](/testing-policies) (relative to the config file) instead of serving. |
| `-explain` | Print the [effective policy](/policies#explaining-the-effective-policy) of every operation instead of serving. |
| `-version` | Print the version and exit. |
